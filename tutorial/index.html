1. 项目概述

本项目是一个面向企业机房资产管理的全栈 Web 应用（CMDB）。它管理机房机器的以下四类信息：

机器硬件信息

系统类型、厂商、序列号、磁盘配置（SSD/HDD）、CPU 型号、内存数量、服务器高度等

网络信息

IPv4/IPv6 地址、MAC 地址、网卡名称、VLAN、网关、网络类型（static/pppoe）、IP 状态

IDC/SSH 信息

ZbxID、IPMI IP（核心关联键）、机房编码与名称、SSH 远程管理 IP

业务信息

业务名称与 ID、新旧业务带宽、业务变更记录

核心功能

  • JWT 认证 — 基于 Bearer Token 的用户登录与角色鉴权（admin/user）
  • 多字段搜索 — 支持机房编码、名称、IPMI IP、业务 ID 等字段的 ILIKE 模糊匹配
  • Redis 缓存 — 机器详情 30 分钟缓存，列表 5 分钟缓存，缓存未命中自动降级查库
  • 多表联查 — 以 ipmi_ip 为核心外键，LEFT JOIN 四张表 + JSON 聚合查询
  • 安全删除 — 删除机器/网络信息前自动归档到 deleted_records 表，JSONB 保存完整原始数据，保留 30 天可恢复
  • Excel 导出 — 所有页面支持按当前筛选条件导出 .xlsx 文件，使用 excelize 库服务端生成
  • Docker / 原生部署 — 支持 Docker Compose 和原生 OpenResty 两种部署模式
数据规模：生产数据库约 1776 条机房记录、1745 条机器记录、3502 条网络记录、1768 条业务记录，覆盖 36 个机房。

2

先查 Redis 缓存（如 ListMachines/GetMachine），命中直接返回。未命中则查 PostgreSQL，结果写入 Redis。

4. 后端详解

4.1 入口文件 main.go

main.go 是程序的启动入口，负责按顺序执行以下步骤：

func main() {
    config.LoadConfig()       // 1. 加载 .env 配置
    database.ConnectDB()      // 2. 连接 PostgreSQL + AutoMigrate + seedUsers
    database.ConnectRedis()   // 3. 连接 Redis（失败不退出）
    r := gin.Default()        // 4. 创建 Gin 引擎

    // 5. 注册公开路由
    r.POST("/api/login", handlers.Login)

    // 6. 注册认证路由组（JWT 中间件）
    auth := r.Group("/api")
    auth.Use(middleware.AuthRequired())
    { /* ... 40+ 路由 ... */ }

    // 7. 启动 HTTP 服务 + 优雅退出
    srv.ListenAndServe()
    // Ctrl+C → 5 秒超时关闭
}
优雅退出：程序监听 SIGTERM/SIGINT 信号，收到信号后 5 秒内完成正在处理的请求，然后安全关闭。避免数据丢失或连接泄露。

NetworkInfo 指针类型：IPv4IP、IPMIIP、ZbxID 等字段使用 *string 而非 string，因为数据库中这些字段允许 NULL。GORM 中 string 的空值是 ""，而指针的零值是 nil，能与 SQL NULL 正确对应。

func ListMachines(c *gin.Context) {

    // 2. 主查询：
    //    SELECT i.*, m.*, b.*,
    //           COALESCE(n.networks, '[]') as network_info
    //    FROM idc_info i
    //    LEFT JOIN machine_info m ON m.ipmi_ip = i.ipmi_ip
    //    LEFT JOIN business_info b ON b.ipmi_ip = i.ipmi_ip

    //        SELECT zbx_id, json_agg(network_info.*) as networks
    //        FROM network_info GROUP BY zbx_id
    //    ) n ON n.zbx_id = i.zbx_id

4.8 Redis 缓存策略

缓存键TTL场景
cache:machine:{ipmi_ip}30 分钟单机详情查询
cache:machine:list:{params}5 分钟机器列表查询（缓存键含查询参数）
network_info:{ipmi_ip}—写操作后删除，下次查询重建
缓存失效策略：所有写操作（创建/更新/删除）执行后立即 DEL 对应缓存键。这是经典的 Cache-Aside 模式。注意：删除 IDC 机房时需要同时删除该机房所有机器的缓存。
Redis 降级：ConnectRedis() 连接失败时不会退出程序，将 RedisClient 设为 nil。所有 Redis 操作通过 nil-safe 包装函数（CacheGet/CacheSet/CacheDel/CacheFlushDB）进行，Redis 不可用时自动降级为直接查库，不会 panic。

router.beforeEach((to, _from, next) => {
  const token = localStorage.getItem('token')
  if (to.name !== 'Login' && !token) {
    next({ name: 'Login' })           // 未登录 → 跳转登录页
  } else if (to.name === 'Login' && token) {

  } else {

  }

5.4 API 请求层 api/index.ts

async function request<T>(url: string, options: RequestInit = {}): Promise<T> {
  const token = getToken()
  const headers: Record<string, string> = {
    'Content-Type': 'application/json',
    ...(token ? { Authorization: `Bearer ${token}` } : {}),
  }

  const res = await fetch(`${BASE}${url}`, { ...options, headers })

  if (res.status === 401) {          // Token 过期
    localStorage.clear()
    window.location.href = '/login'
    throw new Error('Unauthorized')
  }
  return res.json()
}

关键设计点：

  • 自动注入 Token — 从 localStorage 读取，添加到 Authorization header
  • 401 拦截 — 清除本地存储并跳转登录页，防止用户看到错误数据
  • BASE 为空字符串 — API 请求发送到同域，由 OpenResty 反向代理到后端

            try_files $uri $uri/ /index.html;
        }
    }

7. 关键注意事项

7.1 数据库相关

  • GORM AutoMigrate 不修改已有列类型 — 新增列会自动添加，但已有列的类型变更需要手动 SQL 迁移
  • ipmi_ip 是核心关联键 — 所有跨表查询都依赖它。删除 idc_info 时务必使用事务级联删除 machine_info 和 business_info
  • network_info 条件唯一索引 — ipv4_ip 和 ipv6_ip 使用了 WHERE ... IS NOT NULL 条件，允许多条 NULL 记录但非 NULL 值唯一
  • ILIKE 不区分大小写 — 所有模糊搜索使用 PostgreSQL ILIKE 操作符，解决 manufacturer 大小写不一致问题
  • 远程数据库连接 — 本部署方案中 PostgreSQL 在远程服务器（3418.s.kuaicdn.cn:34189），无需本地运行数据库容器

7.2 缓存策略

  • 机器详情 30 分钟，列表 5 分钟 — 详情变更频率低，列表需要更快反映变更
  • 缓存键包含查询参数 — cache:machine:list:page=1&size=300&idc_code=B11...，不同查询条件不会互相污染
  • 写操作后必须清除缓存 — 否则用户看到过期数据。特别是批量操作（如 DeleteIDCByCode）需要清除多台机器的缓存
  • Redis 不可用不阻塞 — 连接失败时程序继续运行但缓存功能不可用，每次请求直接查库。适合 Redis 不是核心依赖的场景

7.3 安全性

  • JWT 密钥管理 — 生产环境必须通过环境变量注入，密钥长度不少于 32 字节随机字符串
  • bcrypt 不可逆 — 密码哈希后无法还原，登录时通过 CompareHashAndPassword 比较
  • 角色鉴权 — admin 用户可以执行危险操作（清空网络信息、删除整个机房），普通 user 只能查询
  • Bearer Token 模式 — Token 存储在浏览器的 localStorage 中，每次请求通过 Authorization header 发送
  • Token 过期 72 小时 — 过期后前端自动跳转登录页（401 拦截）

7.4 部署注意

  • host 网络模式 — 所有容器共享宿主机网络栈，通过 127.0.0.1 互通。确保宿主机端口 34185、34186 未被占用
  • OpenResty SPA fallback — try_files $uri $uri/ /index.html 确保刷新页面时不会 404。但 Hash 路由模式下 # 后的内容不发送到服务器，此配置主要用于首次加载
  • 静态资源缓存 — /assets/ 目录设置 30 天缓存 + immutable，Vite 构建时会给文件名加 hash，内容变更时 URL 会变化，无需担心缓存过期
  • .dockerignore 减少构建上下文 — 排除 .git、node_modules、tutorial、.md 等不需要打包进镜像的文件
  • pnpm 镜像配置 — .npmrc 中设置 registry=https://registry.npmmirror.com 加速国内依赖安装

7.5 前端开发

  • 本地开发 — cd frontend && pnpm install && pnpm dev，端口 34187
  • 生产构建 — pnpm build，输出到 dist/ 目录
  • Hash 路由优势 — OpenResty 不需要为每个前端路由配置特殊规则，# 后的内容完全由浏览器处理
  • TypeScript 类型检查 — build 脚本使用 vite build（跳过 vue-tsc），可在 CI 中单独运行 vue-tsc --noEmit 做类型检查
